# Avito AI Reviewer — единый кабинет

Рабочий прототип единого кабинета для студента, ревьюера и методиста. Core API и данные работают на FastAPI + PostgreSQL, интерфейс — Vue 3. AI Review и Feedback Copilot вынесены в отдельный FastAPI-микросервис и подключены к Z.AI GLM-5.3-Flash через официальный `zai-sdk`; Rubric CI и блиц-анализ пока замоканы.

## Запуск

```bash
cp .env.example .env
# Добавьте ZAI_API_KEY в .env
docker compose up --build
```

После запуска:

- кабинет: <http://localhost:8080> (методист → «Банк заданий и критериев»);
- OpenAPI: <http://localhost:8081/docs>;
- healthcheck: <http://localhost:8081/health>;
- AI Reviewer OpenAPI: <http://localhost:8010/docs>;
- AI-помощник лектора: движок банка заданий, OpenAPI на <http://localhost:8080/task-creater/docs>
  (кабинет проксирует его на `/task-creater/` ради Swagger; прямой порт — `:8082`).

Какие разделы включены — состояние продукта: оно живёт в `api/app/config.py` и едет
вместе с кодом, а не через `.env`. Поэтому обновление стенда — это `git pull` и
`docker compose up -d --build`, без правки файлов на сервере. Что поднялось, api
пишет строкой в лог при старте (`docker compose logs api | grep флаги`).

Порты (кабинет 8080, core API 8081, ai-reviewer 8010, task-creater 8082, postgres 55432) можно
переопределить без изменения файлов:

```bash
UI_PORT=9080 docker compose up --build
```

Поднять только AI-помощник лектора:

```bash
docker compose up --build taskcreater
```

В кабинете методиста всё это живёт в разделе **«Банк заданий и критериев»**
(флаг `FEATURE_RUBRIC_BUILDER`): список заданий → редактор → AI-заполнение блоков →
проверка на AI-персонах (студенты ИЛИ ревьюеры, по одному типу за запуск) →
рекомендации с «Применить / Редактировать / Отклонить» → публикация.

Задание хранит core API, `taskcreater` работает как счётная машина: в него ходит
только api (`TASKCREATER_URL`), браузер — никогда. Поэтому у задания одно
хранилище и одна версия, а не две.

По умолчанию `taskcreater` работает в fake-режиме (детерминированные ответы, без
вызовов LLM) — как и остальные AI-модули этого этапа. Для реальных прогонов задайте
`TASKCREATER_LLM_FAKE=0` и креды шлюза в `.env` (см. `.env.example`). Детали,
сквозной сценарий и проверялка эндпоинтов — в [task-creater/README.md](task-creater/README.md).

В «Аналитике курса» есть блок **«Образовательный долг»**:
темы, которые не усваиваются; задания с одной и той же ошибкой у многих; критерии,
которые ревьюеры переписывают руками; задания, после которых чаще всего приходится
переспрашивать; задания, которые пора пересмотреть. Всё считается по живым работам,
ревью и прогонам агентов на каждую загрузку экрана — кэша нет, момент расчёта показан
рядом со списком. У каждого вывода есть порог наблюдений: ниже порога вывод не делается
вовсе. Градаций важности нет: если признак попал в список, им уже стоит заняться. Из
каждого признака можно перейти в банк — к заданию или прямо к спорному критерию.

На стартовом экране есть демо-вход для каждой роли. База заполняется учебным курсом на 12 студентов и 4 ревьюеров: восемь закрытых заданий с оценками и правками ревьюеров, три задания в работе (только выданное, идущее и с прошедшим сроком) и уведомления. Курс намеренно неровный — одна тема проседает, у части критериев ревьюер регулярно спорит с моделью, у самого старого задания давно не трогали рубрику: на безупречных данных разделу «образовательный долг» нечего показать.

Сев идемпотентен и досеивает недостающее на каждом старте, опознавая людей по e-mail, а задания по названию, — уже поднятый кабинет получает новых студентов и новые задания, не теряя накопленного и не создавая дублей. Задания, накликанные при отладке, убирает `python -m scripts.cleanup_demo` из каталога `api` (без `--yes` только показывает список); задание, по которому кто-то сдавал работу, он не удаляет никогда. Начальные ревью явно помечены как демо-фикстуры. Новая сдача публичного GitHub-репозитория сохраняется как ограниченный снапшот и проверяется через Z.AI. На экране ревью можно повторно прогнать существующую работу реальной моделью.

### Реальный курс вместо демо-данных

Кабинет наполняется настоящими материалами Авито — заданиями, критериями и
решениями студентов из `Product-part/01_Входящие/homework_examples`. **На новой
машине для этого ничего делать не нужно:** пустую базу заполняет старт
контейнера, читая данные из репозитория. Ключ к модели и интернет при этом не
нужны — разборы не пересчитываются, а лежат в `api/data/real_course/ai_results.json`
дословными ответами модели, снятыми одним прогоном.

```
docker compose up -d --build     # и всё; кабинет поднимается с курсом внутри
```

Старт наполняет пустую базу и заменяет нетронутый демонстрационный курс — он
целиком создан севом, терять там нечего. Базу, в которой есть заведённые руками
задания, он не трогает и пишет в лог, почему и что сделать. Заменить осознанно:

```
docker compose exec api python -m scripts.load_real_course --wipe --restore
```

Решение о наполнении всегда видно в логе контейнера (`docker compose logs api`) —
строкой «курс из репозитория …». «После обновления ничего не изменилось» —
самый частый вопрос про этот шаг, и отвечать на него чтением кода по серверам
не должно быть нужно.

Одиннадцать заданий четырёх треков (системный дизайн, аналитика, data science,
продукт) и тридцать три решения, размеченные кейсодателем как слабое, среднее и
хорошее. Формулировки заданий и тексты работ не редактируются; критерии
перенесены из раздела «Критерии оценивания» соответствующего условия вручную и
лежат в `app/real_course.py` — разбирать шкалу оценивания регулярным выражением
из пяти разных форматов означало бы однажды молча выставить балл по неверной
рубрике. Разметку уровня оценка не видит: она лежит в снапшоте рядом с работой,
чтобы потом было с чем сравнить то, что поставила модель.

`--restore` делает четыре шага сразу: загружает задания и работы, проставляет
сохранённые разборы, достраивает решения ревьюера и подтягивает даты к
сегодняшнему дню. Каждый идемпотентен и доступен отдельно:

```
python -m scripts.load_real_course --complete    # решения ревьюера по старым заданиям
python -m scripts.load_real_course --reschedule  # пересчитать даты от сегодняшнего дня
```

Заново прогнать проверку моделью и обновить сохранённые ответы (нужен ключ,
занимает около получаса и стоит денег):

```
python -m scripts.load_real_course --wipe --review   # прогнать по-настоящему
python -m scripts.load_real_course --blitz           # доп. вопросы, где разбор усомнился
python -m scripts.load_real_course --export          # записать ответы обратно в репозиторий
```

Тест сверяет сохранённые ответы с каталогом заданий: если задание добавили или
критерий переименовали, а выгрузку не обновили, это видно до того, как
восстановленный кабинет окажется наполовину пустым на чужой машине.

Настоящих решений ревьюера по этим работам не существует — кейсодатель передал
работы и метки уровня, но не проставленные баллы. `--complete` их достраивает из
метки: ревьюер соглашается с моделью, пока её оценка попадает в диапазон,
ожидаемый для работы такого уровня, и правит там, где расходится, начиная с
выводов, в которых модель и сама менее уверена. Случайные правки дали бы ровный
шум, по которому любая аналитика показывала бы одно и то же. Отклонения вывода
(«rejected») там не появляется вовсе: по одним баллам не отличить «модель
завысила» от «модель сослалась на отсутствующее», а это разные действия.
Достроенные разборы помечены в `raw_result`, чтобы их нельзя было принять за
решения живого человека.

`--blitz` отправляет дополнительные вопросы только по тем работам, где модель
сама выставила сигнал сомнения в понимании, и вопросы к ним генерирует та же
модель тем же вызовом, что и кнопка в кабинете.

`--review` вызывает ту же функцию, что и кабинет при назначении работы
ревьюеру, и ходит в настоящую модель. Отдельного «режима демонстрации» нет: без
ключа работа останется без разбора, и это будет видно. Демонстрационный сев при
следующем старте в такую базу не полезет — он отвечает только за свой курс.

## Сколько это занимает и сколько стоит

Числа измерены, а не оценены: `api/scripts/measure_pipeline.py` вызывает те же
функции, что и кабинет, засекает время и берёт токены из ответа провайдера.
Поэтому запуск замера стоит денег — ровно столько, сколько показывает в своей же
колонке. Результат последнего прогона лежит в `api/data/measurements.json`.
Время каждого обращения к модели теперь пишется в `llm_calls`, так что
статистика копится сама и в проде, а не только в момент демонстрации.

**Ядро кабинета** — z.ai `glm-5.3-flash`, тариф $0.075 / $0.25 за 1M токенов:

| операция | время | токены | стоимость |
|---|---|---|---|
| Проверка работы по критериям | 34.9 с (26–44) | 7 889 → 2 682 | $0.0013 |
| Проверка на признаки AI-генерации | 28.2 с (23–34) | 23 208 → 2 622 | $0.0024 |
| Составить вопросы студенту | 11.8 с (8–16) | 7 329 → 747 | $0.0007 |
| Переписать обратную связь под тон курса | 8.0 с (4–12) | 1 600 → 568 | $0.0003 |
| Распределить очередь из 24 работ | 22 мс | — | бесплатно |
| Подобрать ревьюера для одной работы | 7 мс | — | бесплатно |

По проверке работ есть выборка шире: пакетный прогон всех 33 работ курса дал
медиану 28.6 с при разбросе 17–65 с — время зависит от объёма работы студента.

**Конструктор заданий** — Gemini через шлюз, свой тариф:

| операция | время | токены | стоимость |
|---|---|---|---|
| Создать задание с критериями | 30.1 с | 2 912 → 6 045 | $0.0611 |
| Проверить задание на AI-персонах | 66.6 с (24–109) | 31 543 → 12 544 | $0.0718 |
| Сочинить критерий с градацией | 6.8 с | 1 044 → 580 | $0.0073 |
| Улучшить формулировку блока задания | 3.2 с | 372 → 256 | $0.0030 |

Распределение — единственная автоматизация без модели вовсе: это расчёт, он
занимает миллисекунды и не стоит ничего.

**Сквозная стоимость.** Одна работа: $0.0016 (проверка и обратная связь) —
$0.0047 (плюс детекция и вопросы студенту). Одно задание: $0.061 (только
генерация) — $0.163 (плюс прогон на персонах, три критерия, две правки блоков).
Поток из 12 студентов и 11 заданий — 132 работы — обходится примерно в $1–2.5.

**Что это заменяет.** Ориентиры «как было» лежат в `app/services/effort.py` с
указанием источника у каждого; все они из интервью кейсодателя, а не из наших
предположений. По проверке работ: час на работу до автоматизации, 10–15 минут
после неё на курсе, где AI внедряли своими силами. Отсюда экономия около 47
минут на работу и порядка 100 человеко-часов на поток.

По созданию заданий и распределению интервью даёт только совокупную нагрузку
методиста (до 10 часов в неделю на поддержку процесса) — поэтому поштучной
экономии там мы не считаем: машинное время измерено, человеческое «до» никто не
мерил.

В счёте экономии вычитается время, которое человек тратит после машины: разница
между «модель посчитала 30 секунд» и «работа проверена за 30 секунд» — то самое
место, где расчёт превращается в рекламу. Ставка часа не зашита в код: своих
ставок Авито не раскрывал, и окупаемость в деньгах считается только когда ставку
передали снаружи.

```
docker compose exec api python -m scripts.measure_pipeline --repeat 3
```

## Что реализовано

- настоящий JWT и серверный RBAC;
- ролевой кабинет со всеми экранами проектного решения;
- загрузка публичного GitHub-репозитория, ограниченный неизменяемый снапшот и автомат статусов;
- объяснимое распределение по специализации и загрузке с подтверждением методиста;
- очередь и рабочее место ревьюера;
- реальный структурированный AI Review через Z.AI GLM-5.3-Flash с валидацией баллов;
- Feedback Copilot через Z.AI без автоматического применения результата;
- принятие, изменение и отклонение каждого AI-вывода;
- отдельный AI-use/understanding signal, недоступный студенту;
- подтверждаемый человеком блиц-опрос и публикация результата;
- неизменяемые версии рубрик, настройки курса и демо-аналитика;
- in-app уведомления и фиче-флаги.

## Структура

```text
api/           Core FastAPI: домен, PostgreSQL, GitHub adapter, orchestration
ai-reviewer/   FastAPI: zai-sdk, GLM-5.3-Flash, review и Feedback Copilot
ui/            Vue 3, ролевые feature-модули, nginx
task-creater/  AI-помощник лектора: идея → ДЗ с критериями + мультиагентная
               валидация критериев (LangGraph); отдельная база `taskcreater`
               в общем сервере postgres
```

Core API не получает `ZAI_API_KEY`: секрет передаётся только контейнеру `ai-reviewer`. Фоновую оркестрацию пока запускает Core API, а вызов модели выполняет отдельный сервис. При отсутствии ключа реальный прогон получает статус `failed`, а Copilot возвращает `503`; скрытого перехода на фиктивный результат нет. Интерфейс явно помечает стартовые фикстуры и агрегаты на демо-данных.
